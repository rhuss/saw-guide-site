OpenShell gateway gRPC listener with mTLS.

18789

Target of the dashboard Route, which SAW sets up for the OpenClaw agent web UI. At this baseline the Route does not reach the OpenClaw UI (see Routes).

webui

8080

Routes

Three OpenShift Routes expose each VM to external clients:

Route TLS termination Service port Purpose

Gateway

Passthrough

17670

The openshell CLI connects here. Passthrough TLS preserves the gateway’s own mTLS certificates end to end.

Dashboard

Edge

18789

SAW’s Route for the OpenClaw agent web UI. Forwards to VM port 18789. At this baseline OpenClaw listens inside the sandbox container, which has no network of its own, so the Route does not reach the OpenClaw UI. Users open the UI with openshell forward service instead (see Open the OpenClaw web UI).

Web UI

Edge

8080

The OpenShell Dashboard, fronted by oauth2-proxy (port 8080) inside the VM.
SAW’s Route names are counterintuitive. SAW sets up the Route named dashboard for the OpenClaw agent UI, not for the OpenShell Dashboard, and at this baseline that Route does not reach the OpenClaw UI. The Route named webui reaches the OpenShell Dashboard through oauth2-proxy.

The gateway Route uses passthrough TLS because the gateway performs its own mTLS handshake with client certificates whose OU field carries OIDC roles. The dashboard and web UI Routes use edge termination, so the OpenShift router handles TLS and forwards plain HTTP into the VM.

Governance interceptor port

The governance interceptor listens on gRPC port 18081 in the openshell-agents namespace. The NetworkPolicy restricts ingress to Pods matching kubevirt.io: virt-launcher in namespaces labeled openshell.pattern/saw: "true".
